# Git運用規約

## git操作について

- .git/ 以下のファイルを追加したり、ファイルを編集しないこと
- git add の際はディレクトリの指定はせず、個別のファイルを逐一指定すること。複数ファイルの同時指定は許容される
- コミットの際は追加コミットだけにすること。過去のコミットを後から操作しないように
  - 以下は禁止する。実行したい場合はユーザーに許可を求めること
    - git commit --amend
    - squash
    - rebase (mainと合流する目的であれば merge main をすること)
    - reset

## コミット可能条件

特段の指定のない限り、以下の条件を満たさない限りコミット処理に進まないこと。
テストやフォーマットのタスクの実行時に想定外の事態が発生した場合は指示を仰ぐこと。
勝手にコミットまで進めてはいけない。

- ユニットテストが全ケース成功していること
- code formatterがエラーなく適用されていること

## gh-proxy mcp

- issue の読み取りやPRコメントの取得などができる
- push や pr create もできるが、ユーザーの求めがない場合は利用しないこと

pull requestを作る時に issue url の指定がなかったり、コンテキストから読み取れない場合はユーザーに確認すること。
結果としてissue urlが存在しないケースもあるので、存在しないという回答があった場合はそのままpull requestを作ってよい。
